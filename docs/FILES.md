# Source guide

Yeh guide project ka code map hai. Paths repository root se hain. React components props lete hain aur JSX return karte hain; event handlers state/callback update karte hain aur usually koi value return nahi karte. Effects listeners, timers aur animations set up karte hain; unka returned function cleanup karta hai. Neeche har file ke special inputs, outputs aur dependencies diye hain.

## Layout and units

All application CSS `src/styles/` mein hai. `tokens.css` shared colours, fonts, spacing aur radii define karta hai. Dimensions 16 CSS pixels = 1rem ke baseline par converted hain; root font size fixed nahi hai. Percentage, viewport, container and em units apne original responsive purpose ke liye retained hain.

`CanScene` ka relative `.can-scene__stage` canvas, fallback aur dono absolute splash layers ka common coordinate system hai. Controls ki reserved height stage se ek baar subtract hoti hai. Compact container query isi stage ko resize karti hai. Canvas par extra mobile bleed nahi hai. Ground 86% stage height par hai: current camera se can base approximately isi position par project hota hai. Camera pose, FOV ya model height change karte waqt ground bhi verify karein. The renderer uses measured stage dimensions and `setSize(width, height, false)` so CSS owns the display size.

IntersectionObserver `rootMargin` only pixels/percentages accept karta hai, is liye uske strings retained hain. Pointer coordinates, canvas drawing buffers, image intrinsic width/height, SVG viewBox coordinates and Three.js world units CSS layout dimensions nahi hain. Inhein rem mein convert nahi karna. GSAP/ScrollTrigger runtime transforms aur pin-spacer inline styles generate karte hain; static presentation CSS mein hai. Custom SVG artwork (loader, ribbon and cutaway mask) remains SVG; UI icons use Lucide.

## Audit decisions

Removed `sections/Mascot.jsx`, its CSS and `hooks/useFruitParallax.js`: none was reachable from the application entry. Removed `context/MediaStartContext.jsx`: no provider was mounted, so its only consumer always received true. Highlights now uses its existing viewport gate directly. Removed raw UI icon paths, stale comments and unused callback parameters. Necessary animation layers, accessibility wrappers and asset-generation sources remain.

The asset checker previously required a missing mascot image; it now validates every asset declared in media.js instead. The GoodInsides test now reads the actual `data-index` eye state instead of an obsolete inline CSS variable.

Reference checks: [Three.js responsive canvas](https://threejs.org/manual/pages/responsive.html) and [Lucide CSS sizing](https://lucide.dev/guide/react/basics/sizing). Context7 was unavailable in this session.

Artwork tool details: `optimize-assets.mjs` uses `outputWidth(stem)` to return a target raster width; its loop rotates, resizes and encodes each source as WebP. In `create-artwork.mjs`, `wordmark(x,y,width,height,colour)` places the lettering, and `svg(width,height,contents)` wraps markup in an SVG document. `citrus`, `berry`, `leaf` and `passion` receive position/size/appearance arguments and return fruit SVG fragments. `fruitGroup(slug)` returns flavour-specific fruit markup. `canContents(slug,name,colour,ink,interior)` returns a can illustration or cutaway. `save(name,artwork,width)` writes the vector source and rasterized image using sharp. The generation loops call these helpers for the four flavours.

Validation for this refactor: lint, asset/navigation checks, production build, 9 Node unit tests and 26 Vitest tests passed. All 54 browser cases were covered across the initial suite and focused reruns at 390, 768 and 1440 pixels. The hero regression also reads opaque WebGL pixels to check rendered can height/ground alignment, captures the splash at impact, and checks shorter viewports and 125% root text. Geometry is measured in one browser evaluation so a ScrollTrigger refresh cannot fall between individual measurements.

The old mobile section-height assertion was stale: both original and refactored GoodInsides CSS produced a 969px section at the 390px viewport. Its test now checks reachable serving controls and unclipped vertical content on compact layouts; desktop retains the viewport-height assertion. One navigation run was interrupted by Vite reloading while source was being saved; its unchanged test passed on the final rerun. Browser verification used Chromium emulation, not physical iOS/Safari hardware. Screenshots are in the ignored `test-results/layout-review/` directory.
