# Source guide

Yeh guide project ka code map hai. Paths repository root se hain. React components props lete hain aur JSX return karte hain; event handlers state/callback update karte hain aur usually koi value return nahi karte. Effects listeners, timers aur animations set up karte hain; unka returned function cleanup karta hai. Neeche har file ke special inputs, outputs aur dependencies diye hain.

## Cutaway pointer performance

`src/components/PeekCan.jsx` batches mouse/pen samples into one pending animation frame. `followPointer(event)` stores only the latest client coordinates. Its `updatePointerLens()` callback reads the SVG coordinate matrix once, maps the latest sample and updates the lens. `cancelPointerFrame()` cancels the frame and drops the pending sample; focus, touch positioning, pointer leave/cancellation and desktop blur call it before taking ownership of the lens. `cleanUpPointerTracking()` returns the same cancellation function for unmount and StrictMode cleanup. Existing SVG clipping, touch hints and flavour selection remain unchanged. Dependencies are React refs/callback/effect, requestAnimationFrame and the existing lens hook.

`src/styles/PeekCan.css` no longer contains unused `data-peekable` or silhouette selectors: neither existed in the current markup. `src/styles/Cutaway.css` no longer repeats the row display rule owned by SplitText.css. `README.md` now uses the configured GitHub remote in clone instructions and correctly describes component-owned CSS.

`tests/browser/motion-quality.spec.js` adds a pointer-burst regression. The page callback measures SVG geometry reads, `dispatchMoves()` emits forty samples in one frame, and `nextPaint()` waits two frames. It requires one coordinate read, the final requested lens position, and zero pending reads or lens reopening after pointer cancellation. Existing tests separately exercise selection, repeated section entry and live reduced motion.

Production profiling used four synthetic pointer samples per animation frame for four seconds at 1440, 768 and 390px. At 1440px the original handled 948 events with 948 SVG geometry reads and 3792 coordinate writes; the updated version handled 940 events with 234 reads and 936 writes. Layout counts fell from 997 to 280. The other widths also showed approximately one read per four events. This establishes event coalescing under a burst workload, not a physical-device FPS guarantee. Measured RAF rates were 58.8/58.3/59.5 before and 58.3/56.5/54.3 after at 1440/768/390 respectively; total task time also increased in these separate runs. Therefore no overall FPS or CPU-time improvement is claimed, and the user's intermittent lag still needs confirmation on their browser/device. Profiles and raw metrics are under `test-results/cutaway-performance`; its ignored `profile-cutaway.mjs` probe records CDP metrics, CPU samples and RAF intervals against production preview.

A static relative-import traversal from `src/main.jsx` found no unreachable JS/JSX/CSS source module. This does not prove all exports, CSS selectors or runtime paths are useful. The source scan found no debugger, console.log, TODO or FIXME markers. These checks do not establish that the project is bug-free.

Validation: lint, nine Node tests, 57 component tests, asset/navigation checks and production build passed. Twelve production browser cases passed in 4.1 minutes at 1440, 768 and 390px, covering pointer batching/cancellation, lens alignment and selection, one-time section entry, live reduced motion and SplitText layout. All three cutaway screenshots were visually reviewed. The normal preview port was occupied, so an ignored temporary Playwright configuration used port 4182 without stopping the existing server. Evidence is in `test-results/cutaway-final`. No GitHub push or deployment was performed. The existing silent-4K film release check and real-device performance sign-off remain outstanding.

## React Bits integration

Actual source was retrieved through the connected shadcn MCP `@react-bits` registry, using `Magnet-JS-CSS` and `SplitText-JS-CSS`. These are local, narrowed adaptations of [Magnet](https://reactbits.dev/animations/magnet) and [SplitText](https://reactbits.dev/text-animations/split-text), not unchanged copies or merely visual references. The upstream MIT + Commons Clause notice is retained in `src/components/react-bits/LICENSE.md`. No package was installed. SplitText uses the already installed GSAP plugin as a separate dynamic chunk (3.35 kB gzip in this build); [GSAP's SplitText documentation](https://gsap.com/docs/v3/Plugins/SplitText/) informed wrapping, masks and accessibility handling.

## Layout and units

Existing application CSS `src/styles/` mein hai. Requested footer port has component-owned CSS next to its JSX in `src/components/Footer/`. `src/styles/tokens.css` shared colours, fonts, spacing aur radii define karta hai. Dimensions 16 CSS pixels = 1rem ke baseline par converted hain; root font size fixed nahi hai. Percentage, viewport, container and em units apne original responsive purpose ke liye retained hain.

`CanScene` ka relative `.can-scene__stage` canvas, fallback aur dono absolute splash layers ka common coordinate system hai. Controls ki reserved height stage se ek baar subtract hoti hai. Compact container query isi stage ko resize karti hai. Canvas par extra mobile bleed nahi hai. Ground 86% stage height par hai: current camera se can base approximately isi position par project hota hai. Camera pose, FOV ya model height change karte waqt ground bhi verify karein. The renderer uses measured stage dimensions and `setSize(width, height, false)` so CSS owns the display size.

IntersectionObserver `rootMargin` only pixels/percentages accept karta hai, is liye uske strings retained hain. Pointer coordinates, canvas drawing buffers, image intrinsic width/height, SVG viewBox coordinates and Three.js world units CSS layout dimensions nahi hain. Inhein rem mein convert nahi karna. GSAP/ScrollTrigger runtime transforms aur pin-spacer inline styles generate karte hain; static presentation CSS mein hai. Custom SVG artwork (loader, ribbon and cutaway mask) remains SVG; UI icons use Lucide.
